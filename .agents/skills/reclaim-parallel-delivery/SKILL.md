# Parallel Team Delivery Discipline

1. Inspect actual CLI/teamwork capabilities and quotas in-session. Target 15–20 useful active agents **only if supported**. Role count is not active-process count.
2. Respect any teamwork Phase 1 scoping artifact and approval gate. Use native Antigravity orchestration/subagents, not imaginary direct APIs or external coding assistants.
3. Start with simultaneous read-only discovery: repo, design, research, architecture, security, tests. Freeze route/domain contracts before overlapping implementations.
4. Write `docs/AGENT_LEDGER.md` with role ID, real agent identifier if provided, spawned/running/done/failed, file ownership, blockers, handoff notes and recorded high-water mark.
5. Ensure **one editing owner per file at a time**; prefer Git worktrees, branch isolation, or carefully separated components. Shared layout/types/config merged by a single integrator.
6. Dispatch independent feature modules in waves, not 20 write jobs editing one root app simultaneously.
7. Independent QA should attempt to falsify claims after each integration stage; reopen issues and rerun tests.
8. Record every MCP server/skill's availability, scope, invocation and relevant outcome. Use only those connected and authorized.
9. Report delivered features, deferred tasks, actual peak concurrency and measured test outcome accurately. No false throughput achievements.
